# Excel Layout UI 시안

## 목표

Setting CNC.xlsx / W39의 B동 448대(1~448), A동 352대(449~800)를 셀 위치 그대로 탐색하고, 변경 전후와 사용자 조정을 확인하는 독립 HTML 시안이다. 운영 DB·AI·CAPA 엔진과 연결하지 않는다. 배치 원본과 가상 편집 예시를 구분한다.

## 시각 설계

- 배경 #edf1f5, 작업면 #ffffff, 본문 #203047, 주 행동 #2357c6, 변경 표시 #ce670e, 고정 표시 #516278.
- 글꼴: Windows의 맑은 고딕/Segoe UI. 번호는 굵고 명확하게, 모델명은 보조 텍스트로 표현한다.
- 배치: 상단 작업 제목/행동, 건물·모드·검색 도구, 왼쪽 대형 배치도, 오른쪽 선택 설비·변경 목록. 모바일은 배치도 아래 접이식 상세 패널.
- 형태: 제조 현장의 위치 탐색이 주인공. 불필요한 차트/장식 카드 대신 원본의 비정형 빈 영역과 열·행 정렬을 보존한다.

```text
제목 + 원본 주차                         예시 불러오기 / 초안 저장
건물 B | A | 전체       현재 | 조정안 | 비교       설비 검색
┌──────────────────────────────┬─────────────────┐
│                              │ 선택 설비        │
│      원본 셀 기반 배치도       │ 현재 → 변경      │
│                              │ 모델/공정·잠금    │
│ 미니맵               줌 도구  │ 변경 목록        │
└──────────────────────────────┴─────────────────┘
```

설계 검토: 엑셀의 색을 그대로 진한 배경으로 복사하면 작은 글자의 식별이 어려워 모델별 옅은 배경/좌측 색띠로 바꾼다. 위치와 번호는 보존하고, 설비 마스터의 건물 주석과 충돌할 경우 이번 시안은 제공된 Excel을 우선한다. 셀 격자는 논리 위치이며 실제 거리·통로 폭을 뜻하지 않는다.

## 파일

- `index.html`, `style.css`, `app.js`: 오프라인 실행 가능한 인터랙티브 시안.
- `layout-data.js`: 원본에서 추출한 설비 번호·모델/공정·셀·상대 위치.
- `extract_layout.py`: 원본 읽기 전용 추출과 800대 무중복 검사.
- `verify.cjs`: 설치된 Playwright를 이용한 화면/조작 검증.
- `source-layout-reference.svg`: 원본 셀 위치 기반 비교 도면.

## 동작 범위

줌/핀치/이동, A/B 전환, 검색, 모델 필터, 선택 설비 상세, 현재/초안/비교, 모델·공정 변경, 유지 잠금, undo/redo, 변경 목록, 로컬 초안 저장/복구, JSON 내보내기. 예시 변경은 최적화 결과가 아니다. CAPA/T/T/호환성 미확정으로 운영 확정 적용은 비활성화한다. 한글/베트남어 전환을 제공한다.

## 실행과 검증

`index.html`을 브라우저에서 열거나 저장소 루트에서 아래 명령을 실행한다.

```powershell
python -m http.server 8765 --bind 127.0.0.1 --directory docs/previews/forecast-layout
```

접속: `http://127.0.0.1:8765`. 별도 패키지 설치나 환경 비밀값은 필요 없다. 파일 직접 열기와 HTTP 접속은 브라우저 저장소가 다르므로 초안은 접속 방식별로 구분된다.

검증 명령: `node docs/previews/forecast-layout/verify.cjs`. 테스트가 사용하는 기존 Playwright 경로는 이 PC 기준이며 다른 PC에서는 경로 조정이 필요하다.

2026-09-22 검증: **13개 브라우저 시나리오 PASS**. 별도 SheetJS 판독으로 800대의 원본 셀 번호·바로 아래 모델/공정·건물 범위를 대조했다. A/B/전체 전환, 검색, 줌/이동/키보드, 수동 편집/잠금/undo/redo, 현재/조정안/비교, 저장/복구, 예시·운영 적용 차단, JSON 내보내기, ko/vi, 360/390px 가로 넘침 없음, 두 포인터 pinch, JS 오류 및 외부 요청 없음 확인. 자세한 결과는 `verification.json`.

스크린샷: `screenshots/desktop.png`, `overview.png`, `mobile.png`, `mobile-editor.png`, `mobile-360.png`. 두 포인터 pinch는 브라우저 이벤트 시뮬레이션이며 실제 터치 기기 시험은 수행하지 않았다. 앱 전체 lint/build·운영 CAPA·DB 반영·AI 호출 검증과는 별개다.

## 미응답 운영 질문

1. CAPA 기준: 공장 교대·휴식+사용자 지정 효율 / 이론 100% / 최근 실적 기반 중 어떤 방식인지.
확정 Layout의 모델 반영 시점은 **즉시 반영**으로 결정했다. 현장은 목표를 보며 대기→진행 중→완료를 체크한다.

사용자 지시에 따라 하단 계산표(89행 이후)는 입력·분석·CAPA 기준에서 제외한다. 모델 표기의 C0도 보존하고 CNC1/2로 자동 치환하지 않는다.

## 현장 셋업 시안 (v0.7)

`setup.js`가 브라우저 전용 셋업 예시를 담당한다. ‘변경 예시 보기’ 또는 수동 조정 후 ‘조정안으로 셋업 예시 시작’을 누르면 변경 대상의 목표 모델·공정이 즉시 작업 지시로 고정된다. ‘셋업 현황’에서 설비를 선택하고 ‘셋업 시작’→‘셋업 완료’를 체크한다. 셋업 상태 필터, 아이콘/테두리, 전체 변경 대상 대비 대기·진행·완료 대수, 시안 작업자·시각 기록을 제공한다. 변경 없는 설비는 대상에서 제외한다.

초안 수정/undo와 작업 지시는 분리하고 새로고침 후 작업 진행을 복구한다. 예시는 한 작업 지시 묶음만 제공하며 새 버전 대체·취소·재개·실제 사용자 인증·서버 동시성은 구현하지 않았다. localStorage 저장 실패 시 상태는 유지한다. 완료는 준비 완료 표시이며 실제 생산 시작·설비 상태·실적을 변경하지 않는다. 운영 적용 버튼은 비활성 상태다.

검증: `node docs/previews/forecast-layout/verify-setup.cjs` — 8개 PASS. 목표 즉시 반영, 단계 전이·이벤트, 필터/대상 제외, 초안 편집 독립성, 복구·ko/vi, 360px 현장 조작, 저장 실패, JS/외부 요청 없음. 기존 13개와 합계 **21개**. 결과는 `setup-verification.json`, 화면은 `screenshots/setup-desktop.png`, `screenshots/setup-mobile.png`. 운영 권한/RLS·실제 생산 구간/교대·다중 사용자 경합은 앱 통합 때 별도 검증한다.
